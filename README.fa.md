XBond کارِ پروکسی را از اول تا آخر برایتان ساده می‌کند: کانفیگ‌ها را وارد می‌کنید، اتصال را بالا می‌آورید، استراتژی مسیریابی را انتخاب می‌کنید و فعالیت شبکه را زیر نظر دارید. هسته‌های [mihomo](https://github.com/MetaCubeX/mihomo) و [sing-box](https://github.com/SagerNet/sing-box) داخل خود برنامه جاسازی شده‌اند؛ بنابراین هم کانفیگ‌های Clash YAML و هم sing-box JSON مستقیم اجرا می‌شوند — و اشتراک شخص ثالث هم بدون حساب XBond کامل و بی‌نقص کار می‌کند.

## امکانات

- **یک کلاینت، همه پلتفرم‌ها**: اپ دسکتاپ (ویندوز ۱۰ به بعد، مک، لینوکس)، اپ موبایل (اندروید، iOS)، خط فرمان، کنسول وب و ایمیج داکر — همه از یک مجموعه قابلیت و یک زبان مشترک دامنه بهره می‌برند.
- **موتور دو هسته‌ای**: mihomo و sing-box داخل برنامه جاسازی شده‌اند و بسته به نوع کانفیگ، همان یکی اجرا می‌شود؛ یعنی Clash YAML و sing-box JSON هر دو به‌صورت بومی کار می‌کنند.
- **اشتراک، با حساب یا بدون حساب**: اشتراک شخص ثالث (توکن، URL یا فایل کانفیگ محلی) از همان ابتدا کار می‌کند و حساب لازم ندارد. با ورود به XBond Cloud، اشتراک حسابی و مزایای سرویس هم اضافه می‌شود.
- **سه راه برای در دست گرفتن ترافیک**: پروکسی سیستم، TUN یا فقط پورت — متناسب با دسترسی دستگاه و شرایط، جابه‌جا کنید. نشست کاربریِ بدون دسترسی ویژه هم می‌تواند TUN را به یک سرویس سطح ماشین بسپارد.
- **وضعیتِ صادقانه در سه لایه**: دسترسی به هسته، در دست گرفتن ترافیک و اتصال به اینترنت سه واقعیت جداست و جدا نمایش داده می‌شود؛ «وصل نیست»، «در حال بارگذاری» و «خطا» هرگز خودشان را «وصل» جا نمی‌زنند.
- **فعالیت شبکه زیر نظر شما**: لاگ زنده اتصال‌ها، قواعد مسیریابی، کوئری‌های DNS و آمار ترافیک.
- **تاریخچه اشتراک**: هر به‌روزرسانی یک نسخه باقی می‌گذارد — برگشت به نسخه قبل، سنجاق کردن نسخه، و انتخاب کانال به‌روزرسانی مستقیم یا از طریق پروکسی برای هر اشتراک.
- **سرویس واقعی در پس‌زمینه**: دیمون به‌عنوان سرویس سیستم (سطح کاربر یا سطح ماشین) ثبت می‌شود و همراه سیستم بالا می‌آید. قفل نمونه تضمین می‌کند در هر دایرکتوری داده فقط یک دیمون باشد و خاموشی، تمیز و اصولی انجام شود.
- **مدیریت از راه دور**: از اپ دسکتاپ یا وب می‌توانید کنترلر هسته خارجی اضافه کنید و هدف کنترل را عوض کنید — نمونه‌های پروکسی راه دور هم در همان یک رابط مدیریت می‌شوند.
- **عیب‌یابی داخلی**: `doctor` محیط و دسترسی‌ها را خودش بررسی می‌کند؛ `bugreport` بسته‌ای تشخیصی تحویل می‌دهد که مدارک هویتی در آن کاملاً حذف شده‌اند.
- **به‌روزرسانی و زبان‌ها**: در خط فرمان با `xbond upgrade` و در دسکتاپ با به‌روزرسانِ درون‌برنامه‌ای. رابط کاربری به زبان‌های 繁體中文، 简体中文، English، 한국어 و فارسی در دسترس است.

## شروع سریع

### دسکتاپ

۱. اپ دسکتاپِ پلتفرم خود را از [صفحه دانلود](https://openxbond.github.io/xbond/download/) نصب و اجرا کنید — در اولین اجرا، سرویس محلی ثبت و راه‌اندازی می‌شود. ۲. وارد حساب XBond شوید یا یک اشتراک شخص ثالث وارد کنید. ۳. روش در دست گرفتن ترافیک را انتخاب و اتصال را روشن کنید.

### خط فرمان

```console
$ xbond daemon install             # ثبت و راه‌اندازی سرویس محلی (--scope system سرویس سطح ماشین)
$ xbond login                      # ورود به حساب XBond (در محیط بدون رابط، --device)
$ xbond sub add <token|url|file>   # افزودن اشتراک شخص ثالث
$ xbond up                         # راه‌اندازی هسته پروکسی
$ xbond status                     # وضعیت سه‌لایه، اشتراک‌ها و ترافیک
```

فرمان‌های پرکاربرد در یک نگاه:

| فرمان | کاربرد |
| --- | --- |
| `daemon install [--scope user\|system]` · `start` · `stop` · `restart` · `status` · `uninstall` | نصب و مدیریت سرویس محلی |
| `login [--device]` · `logout` | ورود/خروج حساب XBond؛ `--device` برای محیط‌های بدون رابط، از جریان کد دستگاه می‌گذرد |
| `sub add <token\|url\|file>` · `list` · `use` · `update` · `info` · `remove` | افزودن و مدیریت اشتراک شخص ثالث |
| `sub versions` · `rollback` · `unpin` · `channel` · `edit` · `export` | برگشت نسخه اشتراک، سنجاق و کانال به‌روزرسانی |
| `up` · `down` · `mode [sysproxy\|tun\|port]` | بالا آوردن یا پایین آوردن اتصال، مشاهده یا تغییر روش گرفتن ترافیک |
| `node list` · `select` · `test` | مدیریت گروه‌های سیاست و نودها، تست تأخیر |
| `status` · `conns` · `rules` · `dns` · `logs` | وضعیت سه‌لایه و مشاهده فعالیت شبکه |
| `env` | چاپ متغیرهای پروکسی برای نشست ترمینال |
| `doctor` · `bugreport` | خودارزیابی محیط و بسته تشخیصیِ بدون مدارک هویتی |
| `run --config <file>` | اجرای یک کانفیگ مستقل در پیش‌زمینه، بدون دیمون |
| `upgrade [--check]` · `version` · `web` | بررسی به‌روزرسانی، اطلاعات نسخه و کنسول وب محلی |

### داکر

فرمان استقرار Docker را از صفحه اشتراک XBond Cloud کپی کنید تا همراه با اشتراک، در حالت پورت یا گیت‌وی لینوکس بالا بیاید. نمونه Compose این مخزن هم کار می‌کند:

```console
$ docker compose up -d
```

`http://localhost:19090` را باز کنید تا وارد XBond Cloud شوید یا اشتراک وارد کنید؛ می‌توانید قبل از اولین اجرا `SUB_URL` را هم تنظیم کنید. پیکربندی و وضعیت ورود در والیوم `/data` ذخیره می‌شود، اشتراک فعال خودش به‌روز می‌شود و پروکسی mixed پیش‌فرض روی `127.0.0.1:7890` گوش می‌دهد. برای به‌روزرسانی نسخه کانتینر، `docker compose up -d --pull always` را اجرا کنید.

برای توسعه محلی، `docker build -t ghcr.io/openxbond/xbond:local .` و سپس `XBOND_IMAGE_TAG=local docker compose up -d --pull never` را اجرا کنید. جزئیات در [قرارداد رفتاری Docker](docs/specs/docker-daemon.md).

## سرورها و محیط‌های بدون رابط گرافیکی

XBond برای ماشین‌های بدون دسکتاپ هم ساخته شده است:

- **ورود بدون رابط**: `xbond login --device` از جریان کد دستگاه OAuth می‌گذرد — مناسب داکر، SSH و هاست‌های هدلس.
- **مدیریت از راه دور**: کنسول وب هم ماشین محلی را مدیریت می‌کند و هم رابط کنترلرهای هسته خارجی است — در اپ دسکتاپ یا وب، نشانی نمونه راه دور را اضافه کنید تا هدف کنترل عوض شود.
- **تونل SSH**: پورت مدیریتی دیمون راه دور فقط روی loopback باز است؛ با `ssh -L 19090:127.0.0.1:19090 user@host` رابط مدیریت راه دور در مرورگر محلی شما باز می‌شود. هر کس به این رابط برسد می‌تواند دیمون را مدیریت کند — پورت مدیریتی را به شبکه‌های نامطمئن نشان ندهید.

برای به‌روزرسانی خودکارِ زمان‌بندی‌شده، روی هاست داکر با حسابی که دسترسی Docker دارد زمان‌بندی کنید و مسیر را به پوشه فایل Compose بدهید:

```cron
0 4 * * * cd /path/to/xbond && docker compose up -d --pull always
```

## حساب و اشتراک

خود کلاینت XBond فروش ندارد. ورود، پلن‌ها و مزایای سرویس در کنسول XBond Cloud انجام می‌شود؛ وارد حساب نشوید، چیزی از اشتراک شخص ثالث یا کنترل از راه دور کم نمی‌شود.

## اگر مشکلی پیش آمد

۱. با `xbond status` سه لایه را یکی‌یکی بررسی کنید: دسترسی به هسته ← در دست گرفتن ترافیک ← اتصال به اینترنت. ۲. با `xbond doctor` محیط و دسترسی‌ها را خودارزیابی کنید و طبق راهنمای آن پیش بروید. ۳. هنگام گزارش مشکل، بسته تشخیصیِ `xbond bugreport` را پیوست کنید — مدارک هویتی کامل حذف شده‌اند؛ نه نشانی اشتراک، نه توکن و نه مدارک LocalAPI در آن هست.

## توسعه

این مخزن از زنجیره ابزار pnpm + Go + Rust استفاده می‌کند و `pnpm setup` همه وابستگی‌ها را یک‌جا نصب می‌کند. زنجیره ابزار پلتفرم‌ها و فرمان‌های روزمره:

- [محیط توسعه](docs/dev-env.md): زنجیره ابزار و ورودی‌های روزمره وب، دسکتاپ، موبایل و CLI.
- [AGENTS.md](AGENTS.md): ساختار مخزن، فرمان‌های توسعه و قواعد مشترک.
- [سامانه کلاینت](docs/architecture/client-system.md): میزبان‌ها، قابلیت‌های مشترک و قراردادهای بین‌مخزنی.
- [خط لوله توسعه](docs/specs/dev-pipeline.md): مسیریابی ورودی، پیاده‌سازی، UI، بازبینی و نگهداری.
- [ماتریس تأیید](docs/agents/verification.md): انتخاب فرمان و تأیید پلتفرمی بر اساس دامنه تغییرات.
- [راهنمای انتشار](docs/release.md): امضا، تأیید و فرایند انتشار.

متن‌های رابط کاربری به تفکیک زبان در [`packages/client-ui/src/i18n/messages/`](packages/client-ui/src/i18n/messages/) و متن‌های CLI در `internal/i18n/locales/` قرار دارند — بهبود زبان‌های موجود و افزودن زبان‌های تازه خوش‌آمدید.
