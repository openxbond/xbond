# 任務載體：`docs/tasks/`

本倉庫以本地 Markdown 記錄工作。沿用現有選擇，不以 GitHub Issues 或 `.scratch/` 建立平行帳本。

## 讀寫約定

- 一個未完結功能或跨會話任務一個 `docs/tasks/<slug>.md`，檔名採小寫連字符。
- 小修、純格式及文案可直接以 diff、命令結果與交付摘要完成，不必補票。
- 記錄格式、狀態、依賴及完成條件見 [任務記錄](../tasks/README.md)。
- 分診角色寫於獨立的 `分診：` 行，映射見 [分診詞彙](triage-labels.md)；施工階段寫於 `狀態：` 行。
- 使用者已授權的目標與驗收足夠清楚時，可直接進入實作；`ready-for-agent` 不要求先有獨立 spec。
- 規格需要時才放入 `docs/specs/`；不要把 skills 預設的 `intent.md → spec.md → plan.md` 變成每次工作的前置關卡。

## 工程 skills 的操作映射

| skill 中的操作 | 本倉庫的操作 |
| --- | --- |
| 取回任務／issue | 讀使用者指定的任務檔；未指定時搜尋 `docs/tasks/` 的相關記錄 |
| 發佈任務／issue | 建立或更新 `docs/tasks/<slug>.md` |
| 加標籤／留言 | 更新分診行或記錄決策與證據，不追加聊天逐字稿 |
| to-tickets／切票 | 少量切片放同一任務表；可獨立交付或負責人不同才拆成子任務檔 |
| wayfinder／總控 | 只有需要跨任務導航時才建立總控檔，列出真實存在的子任務相對連結 |
| claim／resolve | 開工前標記進行中；結束時記錄結果、依賴與下一步，狀態依證據推進 |

任務在實作、審查、驗證及合流完成後才標記已合流。保留到結果可由固定提交或 PR 追溯；後續清理時先把未閉環項轉入真實的後續任務，把長期契約移入相關文件。沒有合流證據時不能以刪除任務表示完成。
