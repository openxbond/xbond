# 領域文件

全倉庫採單上下文；共享詞彙表與 ADR。Go、Web、Tauri 與平台接入是實作邊界，不因此建立多份詞彙表。

## 按任務載入

| 觸發條件 | 讀取來源 | 用途 |
| --- | --- | --- |
| 任務涉及業務名稱或跨模組行為 | 根 `GLOSSARY.md`，再讀相關程式碼與測試 | 統一概念，核對當前實作 |
| 產品範圍、旅程、能力或公開文案 | 根 `PRODUCT.md` | 核對產品意圖及平台限制 |
| 視覺、互動、可存取性或響應式變更 | 根 `DESIGN.md`、目標來源及可取得的 surface brief | 沿用設計基準，辨認尚未實作的要求 |
| 決策影響架構或已有 ADR | `docs/adr/` 的相關檔案 | 核對理由、替代方案及限制 |
| 已有長期外部行為契約 | `docs/specs/` 的相關檔案 | 核對承諾、兼容與失敗行為 |
| 功能未完成或跨會話接續 | `docs/tasks/` 的相關檔案 | 讀進度、證據與下一步 |

根 `GLOSSARY.md` 是唯一詞彙表，採 domain-modeling 的格式：每個術語一至兩句定義，附 `_Avoid_` 列明應避免的混用名稱。只保存領域含義，不加入目錄、接口欄位、流程、實作選擇或驗收條款；有實際詞義歧義才新增或修訂。

## 文件邊界

- `GLOSSARY.md` 只定義詞彙，不記流程、路線圖或實作進度。
- `PRODUCT.md` 與 `DESIGN.md` 可包含已確認的目標；它們不證明能力已實作或已通過平台驗證。
- 程式碼及測試是當前實作的證據；規格是對外承諾。兩者不同時辨別 bug、過期契約或有意變更，不能自動遷就任一方。
- ADR 記錄為何選擇；新決策引用並明確取代舊決策，不靜默改寫歷史。
- 不存在的路線圖、舊模組及歷史 ADR 不作上下文依據。路徑以當前工作樹核實。

新增領域詞彙只在已解決歧義時寫入；出現與 ADR 的衝突時，明示受影響決策及重開理由。
