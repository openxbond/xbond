# 任務記錄

`docs/tasks/` 追蹤未完結功能與跨會話工作。小修可直接使用 diff 和交付摘要；任務不是開始寫程式碼前必須取得的許可證。完整流程見 [開發管線](../specs/dev-pipeline.md)，載體映射見 [任務載體](../agents/issue-tracker.md)。

## 兩條狀態軸

`分診：` 使用 [五個分診角色](../agents/triage-labels.md)，表示是否適合 Agent 處理；`狀態：` 表示實際施工階段，兩行分開。

| 任務狀態 | 進入條件                             |
| -------- | ------------------------------------ |
| 待核查   | 重現、需求或影響仍待確認             |
| 待實施   | 目標、邊界與驗收已足夠清楚           |
| 進行中   | 已開始調查、原型或實作               |
| 待驗證   | 實作已就緒，但仍缺必要命令或平台證據 |
| 待合流   | 驗收、相關檢查及審查完成，尚未合流   |
| 已合流   | 有實際合流提交或 PR 可追溯；發佈另記 |
| 已取消   | 已記錄不再處理的決定及理由           |

阻塞時保留真實階段，另寫阻塞及下一步，不把「等待」誤標完成。切片表採待實施、進行中、待驗證、已完成；切片完成不代表整項任務已合流。舊記錄接續時按證據更新，毋須為改詞批量重寫。

## 最小模板

按需要保留章節；沒有規格、ADR、切片或探針就省略相應欄，不填虛構路徑或預設成功。

```markdown
# <任務標題>

分診：ready-for-agent

狀態：待實施

## 目標與邊界

- 目標：<使用者可觀察的改善>
- 非目標：<本次不處理的內容>
- 入口與涉及路徑：<實際來源>
- 相關依據：<已有規格／設計／ADR／使用者要求；沒有獨立 spec 也可開工>

## 驗收

- AC-1：<輸入／操作 → 可觀測結果；對應測試或運行方式>
- AC-2：<失敗／恢復或兼容情境>

## 切片與依賴

| 切片 | 可運行交付           | 驗收 | 依賴 | 狀態   |
| ---- | -------------------- | ---- | ---- | ------ |
| S1   | <第一條端到端窄路徑> | AC-1 | —    | 待實施 |
| S2   | <失敗或恢復路徑>     | AC-2 | S1   | 待實施 |

## 驗證證據

| 驗收 | 命令／操作 | 環境 | 結果與限制 |
| --- | --- | --- | --- |
| AC-1 | <實際執行後才記結果> | <宿主／平台／資料來源> | <通過、失敗或未執行及原因> |

## 審查

- 比較基準／本次檔案：<固定提交或明確範圍>
- Standards：<發現及處理；自查就明示自查>
- Behavior（Spec）：<逐項驗收、回歸及未解問題>
- 探針：<只在需要時記單點破壞、攔截證據及還原結果>

## 接續與交付

- 下一步／阻塞：<下一個具體操作與所缺條件>
- 未完成驗證：<平台、原因及負責接續的人或條件>
- 合流：<實際提交／PR；未合流則明示>
- 發佈：<實際 tag／產物摘要；本機建置則明示未發佈>
- 後續：<真實存在的後續任務連結>
```

## 維護與收尾

- 每完成一個切片更新證據與下一步；記結果，不追加完整會話日誌。
- AC 可直接定義在任務內；跨任務長期適用時再整理到行為規格。引用規格時同時帶檔案與 AC 編號。
- 只有跨多個獨立任務需要導航時才建總控；依賴指向真實任務或切片，不預設不存在的 roadmap。
- 合流與發佈分開。全部必要驗證完成前不能寫待合流；沒有實際合流證據不能寫已合流。
- 後續清理已合流任務前，保存固定提交／PR 的追溯入口，將未閉環工作遷入後續任務；長期契約與決策保存在對應文件。
