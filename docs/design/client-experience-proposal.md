# XBond 跨端用戶體驗與玻璃浮島設計

本文件記錄已確認的跨端內容組織、三檔響應式、互動與狀態設計，與 [DESIGN.md](../../DESIGN.md) 共同作為後續實施依據。設計基準已更新；介面實作、平台能力與驗收結果仍須分別核對。本輪僅更新文件。

最新視覺基準為用戶指定的[桌面參考](references/native-desktop.png)與[手機參考](references/native-mobile.png)，共用規則見 DESIGN.md「原生客戶端視覺基準」。B 方案提供任務分組參考；實施時以原生感主卡、材質、導航與互動為準，不以扁平橫條方案取代。

## 1. 設計結論與範圍

**XBond 應是一個打開後即可理解和操作的隨身連線工具。** 首頁讓人確認代理狀態、使用範圍與目前節點，快速開始、停止或恢復；進階頁面再提供完整策略、配置、監察與排查能力。

已確認的約束：

- 桌面用戶端和流動 App 為主要體驗，桌面以約 960 × 720 的日常視窗建立基準。
- 桌面保留八個入口；流動 App 保留四項常駐底部導覽。
- Web 支援從窄屏到 2K／4K 螢幕的響應式使用，瀏覽器擴充功能的彈出視窗和完整管理頁一併設計。
- 白灰卡片、玻璃擬態、大圓角、柔和描邊和陰影、浮島式佈局；保留 XBond 橙色品牌。
- 日常連線優先，進階能力按需展開；各宿主保留真實能力差異，不把統一視覺誤當成所有操作都相同。

統一的是用語、資訊主次、互動結果、元件和視覺尺度；各端的導覽形態、工作區、代理範圍與權限流程分別適配。

### 設計依據與現況

依據為 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)、[控制目標規格](../specs/control-targets.md)、[介面架構規格](../specs/client-ui-architecture.md)、[擴充功能規格](../specs/extension-host.md)、[Android VPN 規格](../specs/mobile-android.md)及對應當前源碼。部分既有文件混有歷史版面與後續方向；本設計不把它們視作同一個已完成版本。

正式設計基準採桌面八入口、手機四主入口與緊湊／標準／寬屏三檔；介面規格同步其導航和版面要求。本文描述設計目標，不能由文件一致便推定全部功能已完成。

## 2. 使用者真正關心的事

| 使用時機 | 首要問題 | 最短可行路徑 |
| --- | --- | --- |
| 第一次打開 | 如何開始？一定要登入嗎？ | 按宿主提供登入、匯入或連接遠端的真實路徑 |
| 上課／工作前 | 有沒有開？哪些程式會受影響？ | 首頁直接讀狀態和範圍，按一次開始 |
| 某個網站不好用 | 現在用哪個節點？可否換一個？ | 點目前節點，選擇候選，取得明確結果 |
| 使用中 | 還有多少配額？需要處理甚麼？ | 首頁只提示與繼續使用有關的摘要和異常 |
| 出現問題 | 是未啟動、配置、權限、節點還是網站問題？ | 看分層狀態，從相關問題進入對應檢查 |
| 進階調整 | 哪條規則、哪個應用、哪項配置？ | 從專責入口進入有搜尋、篩選和詳情的工作區 |

首頁的注意力順序固定為：**連線主操作與真實狀態 → 目前節點 → 常用模式 → 用量與配置摘要**。速率、記憶體、核心版本、PID、規則數量與配置路徑不因有資料就成為首頁主角。

### 選項的出場規則

高頻且容易理解的操作直接出現；低頻但重要的能力保留清楚入口；需要技術背景的內容在專責頁面或詳情展開。首次使用不要求先理解完整策略組、核心、PAC、TUN 與端口體系。

「進階按需」不等於把錯誤、目前代理範圍或必要狀態摺疊隱藏。資訊是否展開，取決於它能否改變目前行動。

## 3. 共用語義與各端能力

### 3.1 目標、配置與帳號分開

| 概念 | 呈現位置 | 意義與操作界線 |
| --- | --- | --- |
| 控制目標 | 桌面側欄上方；手機緊湊頂部列 | 正在查看和控制的執行端；切換不代表遷移流量或停止前一目標 |
| 目前配置 | 首頁摘要、訂閱／配置頁 | 目前使用的連線設定；配置有效不代表代理已啟動 |
| Cloud 帳號 | 獨立頭像／帳號入口 | 身份、服務與同步；不與控制器或訂閱憑據混為一談 |
| 接管方式 | 首頁常用偏好、網絡設定的解釋與詳情 | 哪些本機流量會經過核心；按宿主提供真實選項 |
| 路由模式 | 首頁與節點工作區的清楚標籤 | 進入核心或擴充功能的流量如何選路，不代表所有裝置流量已接管 |

### 3.2 宿主能力矩陣

| 表面 | 實際操作範圍 | 首頁主狀態／主行動 | 不應暗示的能力 |
| --- | --- | --- | --- |
| 桌面本機 | 本機 daemon、核心及宿主支援的接管 | 啟動／停止代理；分列核心、接管、出口 | 核心啟動即所有應用可用 |
| 流動 App 本機 | 宿主提供的系統 VPN 與核心 | 連接／中斷 VPN；系統授權及隧道狀態優先 | 手機一定支援桌面的系統代理／僅端口模式 |
| Web／桌面遠端 | 選中控制器實際開放的 API | 查看狀態、管理或重新連接目標 | 連上控制器即接管目前瀏覽器或裝置 |
| 擴充功能彈出視窗 | 本擴充功能管理的瀏覽器代理 | 啟用／停用瀏覽器代理；切節點與模式 | 原生核心、裝置 VPN、系統 TUN、全裝置保護 |
| 擴充功能管理頁 | 帳號、策略、網站規則、請求與擴充功能偏好 | 管理目前瀏覽器的代理策略 | 完整 Clash 連線快照或原生核心日誌 |

桌面／一般 Web 可無 Cloud 帳號使用第三方配置或遠端控制；目前擴充功能只接受 XBond 帳號登入及專用配置，不能照搬桌面的通用訂閱匯入。Android 的現有帳號能力亦不等同桌面；跨端設計以能力回報呈現，不以一套固定表單假裝全部支援。iOS 權限與 VPN 流程需獨立宿主驗證。

擴充功能「關閉」及目前的 `direct` 模式是釋放本擴充功能代理設定，介面應稱「跟隨瀏覽器設定」，不能稱「全部直連」。其他擴充功能或企業政策可能仍在控制代理；入口不可達也不能在介面假裝已切直連。

## 4. 資訊架構：八入口、四底欄、兩種擴充功能表面

### 4.1 桌面及完整 Web

八入口保留，以留白分組而非增加另一層選單：上組為日常操作，下組為檢查與偏好。分組是視覺輔助，入口數量及可達性不變。

| 入口 | 唯一核心任務 | 內容閱讀順序 | 完整表單的歸屬 |
| --- | --- | --- | --- |
| 首頁 | 確認和控制目前使用 | 連線 → 節點 → 模式 → 用量及配置摘要 | 只提供高頻捷徑，不承接完整管理表單 |
| 節點 | 選擇策略與候選節點 | 目前組別 → 搜尋／排序／測速 → 候選 → 提供者 | 策略組、節點與提供者管理 |
| 訂閱 | 取得並管理配置來源 | 使用中配置 → 其他配置 → 新增／更新 → 詳情 | 匯入、重新命名、編輯、覆寫、移除 |
| 連線 | 理解及處理活躍連線 | 搜尋／篩選 → 記錄 → 選中詳情 | 單條／全部斷開及連線詳情 |
| 規則 | 查明流量的分流依據 | 搜尋 → 規則 → 提供者 | 規則搜尋、來源狀態與更新 |
| 日誌 | 定位核心事件和錯誤 | 等級／搜尋 → 記錄 → 跟隨控制 | 核心日誌檢視、暫停及清空顯示 |
| 診斷 | 找出問題及下一步 | 問題摘要 → 檢查 → 結果 → 工具及報告 | 連通測試、DNS、Doctor、脫敏報告 |
| 設定 | 調整裝置、網絡及介面偏好 | 常規 → 網絡 → 進階 → 關於 | 端口、局域網、控制器及介面偏好 |

「首頁」與「連線」避免同義：前者為連線控制中心，後者在頁頭明確寫「活躍連線」，側欄文字與圖示提供一致的監察語義。

### 4.2 流動 App

常駐底欄固定「首頁、節點、活動、設定」。活動包含「連線、日誌」，首次預設連線，之後保留使用者上次分區；規則從節點頁及設定的進階入口到達，診斷從狀態問題及設定到達。訂閱從首頁目前配置摘要及設定的「訂閱與配置」進入，不新增第五個底部入口。

### 4.3 擴充功能

彈出視窗是即開即用的快捷面板，不放八項側欄或四項底欄。完整管理頁才承接管理；沿用現有八個語義入口「首頁、節點、帳號、規則、請求、日誌、診斷、設定」。其中帳號對應 Cloud 配置與用量，請求對應瀏覽器請求記錄，日誌對應擴充功能事件，不冒充桌面原生資料。

## 5. 頁頭與全域外殼

### 頁頭是否需要

| 表面 | 頁頭決定 | 原因 |
| --- | --- | --- |
| 桌面首頁 | 不放大「首頁」標題、介紹段或麵包屑 | 導覽已交代位置，首屏讓給連線與節點 |
| 手機首頁 | 一行目標選擇器及帳號；不重複大標題 | 目標不能隱藏，但不應吃掉連線操作空間 |
| 列表／設定頁 | 一行緊湊頁名與主要操作，約 40–48px | 頁名、搜尋與操作具有導航和工作價值 |
| 擴充功能彈出視窗 | 小品牌、帳號狀態、開啟管理頁 | 確認代理範圍和下一步，不做縮小版網站導覽 |

頁頭不用每頁固定一段介紹；說明就近放在模式、欄位或錯誤旁。搜尋屬目前工作區，不放一個無法說清搜尋範圍的全域搜尋框。

### 外殼

桌面在緊湊版面使用八入口抽屜，標準及寬屏版面使用約 176–192px 的玻璃側欄，八個目的地始終保留。側欄品牌下方常駐目標選擇器，帳號入口在下方；收為抽屜時，目標移至緊湊頂列，不能失去目前控制對象。版本號、PID、連續跳動的速率、記憶體等移至關於或活動，不常駐爭奪注意力。

主要內容卡直接浮於中性畫布；不把全部內容包進一張巨大卡片，再層層套卡。頁面標題和列表工具可在卡外，卡片內只處理相關任務。原生視窗標題列、拖曳區及系統按鈕由宿主負責，不重畫假視窗控制項。

## 6. 響應式系統與 2K／4K

### 6.1 收斂為三檔

採用「緊湊、標準、寬屏」三檔，只有兩處主要結構切換。先以 **768px 和 1440px 的可用 CSS 視口寬度**作為實施起點，驗證長文案與文字縮放後再微調；不為平板、2K、4K 或每張卡另建一套版面。

| 版面 | 參考寬度 | 核心安排 |
| --- | --- | --- |
| 緊湊 | 小於 768px | 單欄、主操作優先；完整桌面／Web 導覽收為八入口抽屜，流動 App 保留四項底欄；詳情獨立打開 |
| 標準 | 768–1439px | 完整側欄配合主要內容；首頁採緊湊任務流，列表以查閱及選擇為主，詳情按需打開。960 × 720 客戶端在此檔校準 |
| 寬屏 | 1440px 及以上 | 保持相同任務和控制項尺度，資料頁可讓列表與已選詳情同屏；首頁保持操作集中，配置及用量可在下方並列 |

三檔決定整體結構，檔內由自然換行、彈性欄寬與卡片最小可讀寬度處理，不逐頁列一串精確轉換閾值。例如標準檔較窄時，首頁連線主卡與輔助區可以自然疊放；這不是新增第四檔。導覽只在抽屜與完整側欄之間切換，減少窗口縮放時的形態變化。

目的地由宿主決定：桌面及完整 Web 始終有八入口，手機 App 始終有四個主目的地；尺寸只改變擺放。手機 App 放大後不變成八入口桌面介面。擴充功能彈出視窗始終是快捷面板，其完整管理頁才套用三檔。

### 6.2 各類頁面只保留必要差異

| 頁面類型 | 緊湊 | 標準 | 寬屏 |
| --- | --- | --- | --- |
| 首頁 | 連線 → 當前節點 → 模式 → 配置及用量 | 連線主卡、節點與偏好、配置及用量摘要 | 保持任務流，模式與配置可並列；用量不搶主操作 |
| 節點／訂閱 | 選擇器＋摘要列表，點入詳情 | 搜尋與完整列表，詳情用抽屜 | 列表與已選詳情並列；未選中不留空詳情框 |
| 連線／規則／日誌 | 每筆先顯示關鍵摘要，完整資料可查看 | 對齊列表或表格，詳情按需開啟 | 保留主列表並展示已選詳情，讓相關資訊同屏閱讀 |
| 設定／診斷 | 同序單欄，控制項可換行 | 分組卡片；標籤與控制項就近 | 獨立分組可並列，但單一表單與說明保持可讀行寬 |

不用把所有功能擠進小屏首屏，也不用為填滿大屏而新增內容。收窄時，次要欄位進詳情，功能仍可到達；放寬時，優先讓原本需要打開的相關詳情同屏，保持原有順序與選中脈絡。

2K／4K 使用寬屏這一檔，不再分兩套設計。應用可以使用整個窗口，但首頁主操作群組保持集中，列表與詳情可用較多空間，單一設定組約 640–800px 即可；不同內容按閱讀需要限寬，不給整個產品套同一個最大寬度。字體、按鈕及行高不隨螢幕像素成比例放大。

### 6.3 全部頁面共用的適配規則

- **內容先重排，控制項不縮小**：搜尋、篩選和設定行空間不足時換行；長名稱可增高，網址和命令在自身區域斷行或捲動，整頁不得橫向溢出。觸控操作不依賴 Hover。
- **高度不足就捲動**：主操作、錯誤和最後一項設定必須可達；先減少裝飾留白，不縮字或刪功能。一般頁面只保留一個主要縱向捲動區，避免卡片層層套捲軸。
- **鍵盤與安全區一起計算**：以實際可見區域安排內容，安全區只預留一次；鍵盤打開後欄位、錯誤和提交可見，底欄不與儲存列互相遮擋。
- **尺寸改變不丟工作**：詳情從並列轉抽屜或全屏時保留同一任務的草稿、焦點、搜尋、選中與捲動位置；不重新連線、不重送儲存。關閉面板回到對應觸發點。
- **宿主與閱讀偏好保持有效**：200% 縮放按可用 CSS 寬度重排，大字令卡片自然長高；橫屏、分屏、RTL 和減少動態不另做產品版本。原生返回、VPN 授權及觸控尺度遵從宿主規則。

擴充功能彈出視窗以宿主可用邊界為準，約 360–400px 為期望寬度；優先代理開關、節點及模式，保留一個捲動區。次級選擇在原面板內進入，登入及長表單帶著任務上下文開完整管理頁，不疊多層抽屜。

### 6.4 如何驗收

以手機約 390 × 844、桌面客戶端 960 × 720、寬屏 Web 1920px 為三個主要檢查點，再補 320px 小屏、2K／4K 及兩個切換邊界前後。驗收核心是主操作可達、文字不溢出、詳情與列表關係清楚，以及縮放前後的工作狀態連續。

鍵盤、短視窗、長文案、文字縮放和觸控作為三檔共用檢查，不再拆成更多尺寸分類。這是待實施的設計要求，本輪文件修改不代表已完成界面或真機驗證。

## 7. 首頁：日常緊湊任務流

### 桌面

內容分組以 B 方案為基礎；最新視覺基準採用戶確認的原生感參考圖。桌面左側為圓形連線鍵及分層事實主卡，右側為節點與偏好，下方放精簡用量及配置；手機按相同任務順序單欄呈現，使用浮島底欄。連線主操作明確可感，不以後台式橫條壓平所有任務。

| 區域 | 直接呈現 | 互動與下一步 |
| --- | --- | --- |
| 連線主卡 | 啟停鍵、目前狀態、影響範圍、運行時間；核心／接管／出口三項短事實 | 主鍵文字／可存取名稱明確為「啟動代理」或「停止代理」；目前配置在獨立摘要進訂閱，不重複放入口 |
| 當前節點 | 焦點策略組、目前節點、最近一次測量及口徑 | 整行可點選，開選擇面板；不在首頁平鋪候選 |
| 常用模式 | 分開標示接管方式與路由模式；每組最多三個短選項及一句效果說明 | 按能力變更；TUN 權限原因及結果在相關操作旁 |
| 用量區 | 即時速率、短期真實走勢、本次核心累計；配額另有名稱與來源 | 流量進活動／連線，配額進訂閱；串流中斷時保留歷史並標記停止更新 |

不把記憶體、規則數、核心版本、配置路徑或到期倒數做成首頁 KPI。通知只在影響繼續使用時出現，例如配置更新失敗但仍可用、配額不足、權限被撤銷；一般公告不壓過連線操作。

### 手機

順序為目標列、連線主卡、當前節點、路由模式、配置／精簡用量。第一屏優先容納主操作與換節點入口，圖表與低頻資料可向下閱讀。底部導覽保留安全區，最後內容能完全捲到導覽上方。

系統 VPN 是手機本機接管的主要表達；接管方式不能機械複製桌面的三選項。原生 VPN 可用時，使用「連接 VPN／中斷 VPN」，首次操作再按系統流程授權。取消授權回到可理解的未連線狀態，不能顯示成功或反覆彈窗。

### 遠端首頁

明顯標示遠端名稱和操作範圍，主行動為管理或重新連接；有資料才展示遠端可用的核心狀態與路由。遠端無本機啟停能力時，移除電源鍵而不是保留一顆只會開設定的假啟停鍵。手機查看遠端時同樣不顯示本機 VPN 已連線。

## 8. 其餘七頁的內容、版面與操作

### 節點

先看目前策略組與其選中節點，再搜尋、排序及測速。緊湊及標準版面使用組別選擇器與候選列表；寬屏讓列表與已選詳情並列，保留相同的策略組上下文，不再常駐第三條策略目錄。候選節點採一張連續列表，每列約 48–56px，不每個節點一張大卡。

每列優先為名稱、必要來源／地區、延遲及選中標記；協定、鏈路和完整名稱進詳情。使用同一測試口徑比較延遲，未測量、測試中、失敗、上次結果分別呈現。自動策略組不顯示可手動選中的假按鈕；直連模式明確說明節點偏好目前不生效。

手機選節點用可展開底部面板，長列表可轉全高；搜尋與目前策略組固定在面板頂部。切換成功留在原位置並回應，不強制跳回首頁。返回及重開保留同組搜尋與捲動位置，切換控制目標後重新核對。

### 訂閱與配置

使用中的配置置頂，其他配置以中密度列表呈現。每項先顯示名稱、來源類型、目前有效性、最近更新；有配額才顯示已用／總額、餘額與有效期。到期與流量重設是不同日期，不能只寫一個「剩餘天數」。

主操作為使用或更新；重新命名、複製、覆寫、編輯與移除進更多選單或詳情。新增是單一入口，進入後再選登入 Cloud、URL、檔案或貼上，依實際宿主能力提供。首次匯入需要清楚進度及結果；更新失敗保留上一份有效配置，不能移除使用中的可用版本。

購買及續費到 Cloud 控制台，用戶端只交代權益與下一步。不同控制目標的配置不可無標示混列；若配置由本機 daemon 擁有但目前在看遠端，必須標明管理的是本機來源，不能讓操作去向不明。

### 活躍連線

預設呈現應用／目標、所用策略、速率及持續時間；IP、端口、完整鏈路及原始匹配規則在選中詳情。沒有應用名稱時以實際可得的網域／位址呈現，不虛構應用辨識。

緊湊版面為摘要列進詳情；能容納主要欄位時轉資料表，寬度足夠則讓資料表與已選詳情並列，不足時詳情為覆層抽屜。資料刷新或版面變換不重排焦點或移走選中行；預設排序可穩定掃讀。斷開單條就近操作，斷開全部有影響確認，與搜尋及篩選分開。

### 規則

頁面圍繞「這類流量按甚麼規則處理」，提供類型、匹配內容與目標策略的連續列表。提供者更新與規則查閱分區；不混入 DNS 表單。規則搜尋無結果時保留查詢及清除入口，未知命中結果不以猜測的節點替代。

擴充功能網站覆寫與原生核心規則共用詞彙，但不假設具有相同規則能力；精確網域／含子網域的範圍必須在編輯前明示。

### 日誌

頁頭只留等級、關鍵字、暫停跟隨及清空顯示。主要高度交給記錄，時間、等級與訊息對齊。暫停跟隨、停止收集、來源中斷和沒有新記錄是不同狀態。

使用者向上捲動時暫停自動跟隨，提供「返回最新」及新記錄數；不把畫面搶回底部。清空顯示不暗示已刪除核心資料。匯出與分享先說明脫敏範圍，不自動複製原始憑據。

### 診斷

先交代目前已知問題與最近測試時間，再提供「檢查連線」及結果。結果為可理解的項目與下一步：核心、接管、DNS、出口及必要來源連通；不以一段 JSON 作主要界面。

常用網站、DNS、Doctor 與報告屬不同工具，按能力提供。測試結果標記目標、時間與執行位置；瀏覽器直接測試、核心代理測試和手機 App 自身請求不能混稱同一條代理鏈路。失敗保留詳細原因與重試，尚未執行用中性狀態。

### 設定

採緊湊標題列和四個分類，不另加永久第二側欄。窄窗口單欄，空間足夠後可讓同分類的獨立設定組並列；長編輯表單保持自身行寬。每張卡包含同類設定行，標籤、解釋與控制項保持鄰近，避免每個開關獨佔一張卡。

| 分類 | 內容 | 操作規則 |
| --- | --- | --- |
| 常規 | 主題、語言、動態效果、節點切換偏好；宿主已支援的啟動及關窗偏好 | 小型偏好直接生效；有中斷後果的選項說明影響 |
| 網絡 | 接管、端口、跟隨配置／覆寫、局域網、終端命令 | 依能力顯示；數值輸入有驗證、儲存及生效回應 |
| 進階 | 控制器管理、核心相關能力、規則與診斷入口 | 技術資料可複製；不堆積所有未分類項目 |
| 關於 | App／核心版本、已取得的宿主資訊、說明及報告 | 不虛構 platform／arch；不把核心版本放成首頁主要數字 |

設定搜尋列為設計目標，需具備真實索引與可達結果才實施，不先放裝飾搜尋框。帳號與權益有獨立入口，不強迫使用者進「關於」或查控制器才能找到。

## 9. 瀏覽器擴充功能的完整設計

### 9.1 彈出視窗

以約 360–400px 可用寬度、約 480–600px 內容高度作設計基準，實施時服從宿主可用邊界和縮放。內容按以下順序：

1. 品牌、帳號狀態及開啟完整管理頁。
2. 「瀏覽器代理」目前狀態與開關，一句清楚範圍說明。
3. 目前節點／策略選擇，短列表或原位次級面板。
4. 「規則／全局／跟隨瀏覽器」模式，並說明目前選項效果。
5. 目前網站的規則摘要及處理入口；無可取得網站上下文時不顯示假的網域。
6. 配額或需要處理的錯誤摘要；不放假核心流量、記憶體和完整走勢。

目前網站處理是貼近任務的設計目標：可回到規則、指定策略或明確直連，並交代僅此網域／含子網域。實際是否生效依目前路由模式與已編譯規則確認；全局模式下不把無效的網站覆寫顯示為「已生效」。如果需要新增瀏覽器權限，先列入實施決策，不為設計默默擴權。

避免在彈出視窗嵌套對話框、長設定表單或設備登入流程。登入、新增多項網站規則、完整診斷與歷史到管理頁；帶入原任務的目的地及策略組，不一律跳首頁。彈出視窗關閉不表示取消已送交 background 的操作，重開時讀取實際結果。

### 9.2 完整管理頁

採同一玻璃浮島、字體、狀態與響應式規則，使用宿主相符的八入口。首頁仍為瀏覽器代理操作中心，帳號提供登入、配置更新、配額及權益入口；請求頁是明示開始／停止的瀏覽器記錄，不預設偷偷記錄所有瀏覽。

請求是否完成、耗時及預測路由分開表達。PAC 推算結果可稱「規則預測」，不能冒充已實測的出站節點；擴充功能現有記錄也不是原生核心的活躍連線，不能提供沒有來源支援的「斷開此連線」。

### 9.3 擴充功能特有狀態

| 狀態 | 使用者應看到甚麼 | 主要下一步 |
| --- | --- | --- |
| 未登入／等待登入 | 登入要求或授權中的明確進度 | 在管理頁完成／取消登入；過期後重新開始 |
| 沒有可用配置 | 帳號已登入，但配置尚未就緒 | 更新配置或前往帳號處理；不提供第三方匯入假入口 |
| 已套用代理 | 代理設定已套用；連通性另有最近檢查 | 可測試連通；不直接宣稱所有網站正常 |
| 入口不可達 | 最近觀察到入口錯誤及時間 | 重試／診斷，保留恢復路徑，不靜默直連 |
| 認證失敗 | 認證被拒絕，配置或登入可能需更新 | 更新或重新登入，不循環跳原生認證對話框 |
| 代理控制權被取走 | 企業政策或其他擴充功能正在控制 | 解釋原因及重新檢查；不自動搶回控制權 |
| 已關閉／跟隨瀏覽器 | XBond 已釋放自身設定 | 說明可能受其他瀏覽器代理設定影響 |

工具列徽章只用於重要狀態，名稱和可存取文字同時表達；不能只有紅綠點。背景休眠或喚醒不產生無意義的成功通知。平台尚待驗證的背景恢復能力保留限制，不用介面動畫掩飾。

## 10. 核心操作的互動契約

| 操作 | 立即回應 | 完成／失敗後 | 是否需要確認 |
| --- | --- | --- | --- |
| 啟動／停止代理 | 按鈕呈現進行中並防重複；保留目前目標與配置 | 讀取真實核心／接管結果；部分完成分列 | 日常啟停不每次彈確認；有特殊中斷後果則先說明 |
| 手機 VPN 首次連接 | 解釋要取得的系統權限，再開宿主授權 | 取消回到未連線；被撤權呈現可恢復入口 | 系統授權由使用者處理，不能繞過 |
| 換節點 | 候選列顯示切換中，原選中保留 | 成功才更新；失敗就近回應並可重試 | 預設不彈確認；斷開舊連線偏好有明確影響說明 |
| 切換控制目標 | 顯示新目標載入並隔離舊資料 | 保留目標身份，失敗可重試或返回 | 不假裝遷移流量；未儲存編輯另行處理 |
| 更新配置 | 在該配置顯示進度及可取得的下載資訊 | 成功更新時間；失敗保留上一可用配置 | 一般更新不彈確認，重載影響需預先交代 |
| 改模式／開關 | 控制項顯示待處理，阻止同一設定重複提交 | 成功後選中才改變；失敗保留原值及原因 | 不可無成本樂觀偽裝成功 |
| 改端口等輸入 | 保留草稿、就近驗證，提交前可修改 | 儲存成功與重啟／重載結果分開表達 | 有離開未儲存草稿時才提醒 |
| 複製 | 在原位置顯示「已複製」 | 失敗保留可選文字及手動複製 | 不彈確認、不複製額外敏感內容 |
| 移除配置／斷開全部 | 清楚標示影響對象及範圍 | 完成後回到穩定列表位置 | 無法可靠復原的操作需確認，避免假撤銷 |

共享狀態應在所有可見表面一致：節點頁選中、首頁摘要、托盤／VPN 通知及擴充功能徽章來自相同事實。關閉面板不是取消已開始的核心操作；結果未知時先重新核對，不盲目重送。

## 11. 動畫：功能、時間與降級

動畫用來交代位置、狀態和操作結果。視窗打開後內容直接可見，不做逐卡進場、漂浮粒子或全頁呼吸。玻璃模糊是靜態層次，不是常駐運算的背景特效。

| 場景 | 建議時長／方式 | 目的與限制 |
| --- | --- | --- |
| 按壓／Hover／焦點 | 約 80–120ms，輕微明暗或按壓 | 不使整張卡漂移，不讓文字位置跳動 |
| 分段選中／開關滑塊 | 約 140–180ms，無回彈 | 收到結果後交代選中變化；待處理另有指示 |
| 抽屜／底部面板 | 約 180–240ms，短距位移及淡入 | 保留來處，關閉回到原觸發點 |
| 頁面切換 | 即時內容替換或至多 120–160ms 淡入 | 不延遲導航；返回保留位置，不整頁飛入 |
| 啟停中 | 可辨認的進度指示及動詞 | 只作用於相關控制區，不讓整頁變灰 |
| 已知運行狀態 | 可選單一低幅光環，約 2.4s | 只表達已知核心／VPN 狀態，不等同安全或連通承諾 |
| 圖表更新 | 低成本更新或極短插值 | 不模擬沒有的新樣本；離開畫面／後台暫停不必要繪製 |

一般過渡沿用無超調的 ease-out；旋轉只用於確實待處理的進度。啟用減少動態效果時取消循環、位移及縮放，以文字、位置和靜態圖示保留資訊。減少透明度或不支援背景模糊時改用實色表面，不能犧牲文字對比。

## 12. 回饋、等待與注意力

| 回饋層級 | 適用情境 | 保留與消失規則 |
| --- | --- | --- |
| 控制項原位 | 複製、切節點、改開關、儲存 | 最靠近操作；完成後恢復穩定標籤，避免位移 |
| 欄位／區塊訊息 | 輸入錯誤、更新失敗、權限不足 | 原因及下一步留到更正，不自動消失 |
| 頁面狀態列 | 目標失聯、來源中斷、配置不可用 | 直到恢復或使用者處理；不以多次 Toast 洗版 |
| 短提示 | 不需後續行動的低風險完成 | 約 3–5 秒並支援聚焦／懸停保留；重要結果不能只靠它 |
| 系統通知 | App 在後台且發生有意義的斷線／權限變化 | 按宿主與使用者偏好；不每次取樣或成功輪詢都通知 |

操作應立即呈現已接收的可見回應，實際耗時取決於來源；約 300–500ms 仍未完成再增加進度或局部骨架，避免瞬間閃爍。已有內容時不清空整頁換骨架。長時間操作說明目前階段；只在有真實進度時顯示百分比，超時依真實契約判定，不能過幾秒便擅自改成失敗。

無法取消的操作不畫假取消鍵。可以安全返回時讓使用者繼續其他工作；重新打開讀取實際結果。相同故障合併回饋，恢復後一次說明即可。即時速率不透過 aria-live 每秒打斷輔助技術，操作結果才適度宣告。

## 13. 狀態模型與內容文案

**未知、載入中、未啟用、進行中、成功、部分完成、失敗和資料過期是不同事實。** 主狀態、事實列及可操作按鈕需要同時一致，不能由一個漂亮圓環替代判斷。

| 情境 | 建議呈現 | 下一步 |
| --- | --- | --- |
| 尚未取得狀態 | 「正在讀取此裝置狀態」 | 失敗後保留此裝置身份及重試 |
| 沒有配置 | 「加入配置後即可開始」 | 宿主對應的登入／匯入／遠端路徑 |
| 核心停止 | 「代理尚未啟動」 | 啟動代理；依賴頁面解釋暫無資料 |
| 核心已啟動、出口未知 | 「代理運行中」「出口尚未驗證」 | 需要時執行檢查，不宣稱所有連線正常 |
| 僅端口運行 | 「代理端口已就緒，尚未接管系統流量」 | 按需要設定應用或切接管方式；不是故障 |
| 直連模式 | 「目前使用直連模式」 | 節點偏好保留但不冒充目前出口 |
| 手機 VPN 權限被撤銷 | 「VPN 已中斷，需要重新授權」 | 使用者主動重新連接，不循環請求 |
| 更新失敗、舊配置仍可用 | 「更新未完成，仍在使用上次配置」 | 重試及上次成功時間 |
| 資料串流中斷 | 「即時資料已暫停 · 上次更新時間」 | 重試；歷史保留，不補假零值 |
| 搜尋無結果 | 「找不到符合條件的節點／記錄」 | 清除篩選，保留搜尋內容 |
| 配額未知 | 「未有配額資料」 | 查看來源或重新整理，不畫滿環／空環 |
| 配額不足／到期 | 如實列出配額或有效期與已知限制 | 到 Cloud 處理；不捏造價格、續費或立即斷線承諾 |

狀態按鈕用動詞，狀態文字用事實，例如「停止代理」與「代理運行中」分開。避免無條件「已連線」「安全保護中」「全速」「全網可用」。技術錯誤可展開或複製，但主訊息先告知使用者發生甚麼與可做甚麼。

## 14. 設計系統與元件語言

### 14.1 材質與深度

| 層級 | 設計目標 | 使用限制 |
| --- | --- | --- |
| 畫布 | 極淺中性灰，有輕微明暗層次 | 不放光團、地圖、網格等無助操作的裝飾 |

陰影採一套共享尺度：一般工作卡約 `0 4px 16px` 的低濃度向下擴散；浮層約 `0 12px 32px`，顏色及濃度按主題校準。髮線描邊只用於輪廓和玻璃內高光，不再加第二套外框／光暈。實際數值與對比度在實施時共同校準，不能逐頁自由疊陰影。

### 14.2 色彩、形狀與字體

| 項目 | 擬定尺度／規則 |

## 15. 可用性、無障礙與效能要求

- 所有高頻操作可用鍵盤完成，焦點清楚且不被浮島遮住；圖示軌道有可存取名稱及聚焦提示，不只在滑鼠 Hover 才可理解。
- 對話框僅用於需要中斷或保護的任務；開啟管理焦點，關閉回到觸發點；底部面板可返回，不靠拖曳作唯一關閉方式。
- 非機密的未儲存編輯有離開保護，清楚分辨套用中與草稿；導航和查閱不中斷正常操作。
- 手機安全區、鍵盤及橫屏獨立處理；鍵盤打開時固定操作不覆蓋輸入，最後內容可捲到可見範圍。
- 控制器、配置、節點名稱測試長名稱、混合語言與無空格字串；主要狀態及操作不能因省略號失去意思。
- 支援繁中、簡中、英文、韓文與波斯文等既有語系；RTL 使用邏輯方向，地址及協定保持適當 LTR，避免依硬編碼左右定位破壞佈局。
- 即時數據合併更新，不把整頁每秒重建；列表按需要採虛擬化，保留選中與捲動錨點。
- 背景模糊集中於少數外殼，避免每列／每張子卡建立模糊層；背景頁、最小化視窗及不可見圖表停用不必要動畫及繪製。
- 密度預設為舒適；連線、規則、日誌可提供緊湊資料呈現，但不縮小字體和觸控操作區。彈出視窗優先減少內容，不靠縮小所有元件塞滿。
