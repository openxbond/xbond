# 控制目標與首次接入

## 範圍與入口

本規格定義共享 Web／桌面介面如何選擇有效控制目標、授予本機操作能力，以及在本機未有配置時接入遠端。來源入口為 `packages/client/src/controller.ts`、`packages/client-ui/src/state/controller-target.ts`、`state/local-runtime.ts`、`app/app-shell.tsx` 及 `features/configuration/`。現有核心能力與頁面資料見 [介面規格](./client-ui-architecture.md)，宿主與傳輸歸屬見 [用戶端體系](../architecture/client-system.md)。

## 行為契約

### 目標、配置與帳號

控制目標決定命令與資料所屬的執行端；配置決定該端使用的代理設定；Cloud 帳號代表目前登入身份。三者分別管理。遠端控制與第三方配置不要求 Cloud 帳號；切換目標不會自動停止前一個目標或轉移流量。

配置管理保留資源列表及詳情兩欄。列表選擇只開啟詳情；「使用此配置」才提交使用動作。普通來源與 Cloud 來源在後端確認 activeId 後切至本機控制目標，頁頭、列表及快捷入口共用目前使用狀態；啟用失敗保留原來源與控制目標。Cloud 未有有效配置時先同步及校驗，成功才啟用；登入成功本身不表示配置已就緒。帳號來源獨立放在 Cloud 入口，普通訂閱清單不重複列出。

配置更新與使用共用忙碌狀態，詳情與快捷入口在進行中禁止互相衝突的動作。後端確認後的資料重讀失敗由對應查詢顯示，不能把已完成的使用動作誤報為啟用失敗。

首期共享介面辨認兩類目標：目前宿主連接的 XBond daemon，以及外部核心控制器。只有已確認連通且目前選中的 daemon 才能提供本機啟停、接管模式與本機配置操作；外部核心控制器按自身 API 的能力操作。Cloud Agent 的資料面入口不因此成為用戶可管理的核心控制器。

### 有效目標解析

控制目標是判別聯合：本機 daemon（宿主身份，不是已儲存列表的條目）、外部核心控制器（用戶顯式添加），以及「無目標」（純 Web 且未保存任何外部控制器）。存儲鍵 `external-controllers.v1` 只存外部條目，`target.selected.v1` 記錄選擇。

1. 由用戶選擇開始：本機，或某條已儲存的外部控制器。選中的外部條目不存在（已刪除）時回落——有 daemon 宿主回落本機，純 Web 回落第一條已儲存項，都沒有則無目標。
2. `external-controller` metadata 只在本機分支填充端點：daemon 廣播的核心端點（status）優先於 meta，daemon 重啟更換核心端點後跟隨最新快照。尚未取得首次狀態時保留本機身份供載入／失敗處理，不授予寫能力。
3. 宿主提供的 ClashX bridge 優先於 URL 控制器參數，屬外部核心控制器。
4. 沒有 bridge 時，帶 `host` 的啟動參數指定外部核心控制器——即使當前選本機，也不取得本機能力；端點改變而沒有明確提供新憑據時，清除憑據，包括 metadata 注入的 daemon 核心憑據。一般導覽參數不改變目標身份。
5. 無效 metadata 或無法解析的啟動設定保留上一個可用目標；此行為不代表無效設定成功連線。

核心 API 的 HTTP／WebSocket 傳輸與 LocalAPI 能力使用同一個解析結果。不能僅憑已儲存 ID 決定把請求送到 daemon。

### 首次接入

選中並連上本機 daemon、目前缺少可用配置時，首屏提供「登入 XBond」「匯入配置」「連接遠端控制器」。登入與三種匯入方式保留既有流程；本規格新增的遠端路徑不需要先完成登入或匯入。

連接遠端開啟空白的新增表單，支援名稱、地址、憑據與連接測試。成功儲存會產生新的控制器 ID 並選中它；本機身份獨立於列表，不受影響。取消保留原有狀態。連接測試與儲存分開：儲存不是連通成功的證據。

已有遠端目標，包括啟動參數指定的遠端，不受本機是否有配置或 Cloud 登入狀態影響。登入等待或本機無服務時仍可選擇連接遠端；既有登入作業仍由 daemon 管理，切換目標不表示已取消它。

## 邊界與失敗

- 遠端視圖不暴露本機 LocalAPI client、配置、狀態或啟停／接管操作；誤用本機操作明確失敗，不靜默返回成功。
- 已配置本機目標的身份不隨暫時失聯變成遠端；初次讀取失敗時保留本機錯誤與重試入口，未確認連通時不授予可寫的 LocalAPI client。
- 本機帳號與訂閱資料仍由 daemon 擁有；本規格沒有將其轉發到外部控制器，也沒有實作遠端 xbond 管理 API 的完整配對。
- 控制器連接錯誤仍沿用現有錯誤與測試指引；不放寬 Origin、跳過憑證或自動修改系統代理。
- 本次能力判定不等於原生 VPN、TUN、外部連通或 Cloud 登出的驗證。純 Web 也不會因選中遠端就接管目前設備流量。

## 驗收條件

| 編號 | 可判定結果 | 驗證入口 |
| --- | --- | --- |
| TARGET-01 | 宿主聲明的 daemon 取得本機身份與能力；外部條目與「無目標」不取得 | `packages/client/tests/control-target.test.ts` |
| TARGET-02 | 帶控制器啟動參數的目標即使當前選本機也使用遠端傳輸，不顯示本機配置與控制 | 目標解析測試；隔離瀏覽器指定遠端並讀取不同端口的設定 |
| TARGET-03 | daemon 重啟更換核心端點後跟隨最新快照；bridge 優先；一般導覽參數不改變本機身份；跨端點啟動不繼承上一目標憑據 | 目標解析測試；隔離瀏覽器狀態快照輪換 |
| TARGET-04 | 本機無配置時可新增、測試、儲存並選中遠端；本機身份不受影響 | 隔離瀏覽器，使用可區分的本機／遠端接口替身，核對 storage 與請求 |
| TARGET-05 | 已儲存遠端與 URL 遠端不被本機首次接入流程阻擋，切換與路由模式操作不寫本機 LocalAPI | 隔離瀏覽器，核對遠端設定值與兩端寫入請求 |
| TARGET-06 | 三入口文案覆蓋全部語系；窄屏、深色、長文案、鍵盤操作與表單取消可用；本機讀取 503 顯示本機失敗與重試 | 型別檢查；桌面／窄屏瀏覽器檢查 |
| TARGET-07 | 空外部列表 + 無 daemon 宿主 = 首屏即外部控制器表單，不出現任何目標卡片或佔位地址 | 目標解析測試（none 分支）；純 Web 瀏覽器檢查 |

## 已知限制

瀏覽器接口替身只驗證介面解析、傳輸去向與狀態，不證明真實核心、跨來源部署或代理出站成功。原生執行端與完整平台能力的接續，由 Cloud 的客戶端開發計劃與對應控制目標任務維護。
