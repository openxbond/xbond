# 控制目標與首次接入

## 範圍與入口

本規格定義共享 Web／桌面介面如何選擇有效控制目標、授予本機操作能力，以及在本機未有配置時接入遠端。來源入口為 `packages/client/src/controller.ts`、`packages/client-ui/src/stores/request.ts`、`stores/localapi.ts`、`containers/App.tsx` 及 `containers/Onboarding/`。現有核心能力與頁面資料見 [介面規格](./client-ui-architecture.md)，宿主與傳輸歸屬見 [用戶端體系](../architecture/client-system.md)。

## 行為契約

### 目標、配置與帳號

控制目標決定命令與資料所屬的執行端；配置決定該端使用的代理設定；Cloud 帳號代表目前登入身份。三者分別管理。遠端控制與第三方配置不要求 Cloud 帳號；切換目標不會自動停止前一個目標或轉移流量。

首期共享介面辨認兩類目標：目前宿主連接的 XBond daemon，以及外部核心控制器。只有已確認連通且目前選中的 daemon 才能提供本機啟停、接管模式與本機配置操作；外部核心控制器按自身 API 的能力操作。Cloud Agent 的資料面入口不因此成為用戶可管理的核心控制器。

### 有效目標解析

1. 由已選的已儲存控制器開始；缺失的選擇回到可用的已儲存項。
2. 有效的 `external-controller` metadata 可改變目標；必須同時符合已知 daemon 的身份、端點與憑據，才取得 daemon 操作能力。尚未取得首次狀態時保留已配置的本機身份供載入／失敗處理，不授予寫能力；已驗證的相同 metadata 在目前頁面內保留綁定，daemon 重啟更換核心端點與憑據後跟隨最新快照，不重新套用舊核心地址。不同 metadata 不沿用這份綁定。
3. 宿主提供的 ClashX bridge 優先於 URL 控制器參數，屬外部核心控制器。
4. 沒有 bridge 時，有效的 `host`、`port`、`protocol` 或 `secret` 啟動參數指定外部核心控制器；即使沿用預設控制器 ID，也不能繼承本機能力。端點改變而沒有明確提供新憑據時，清除上一目標的憑據，包括 metadata 注入的 daemon 核心憑據。一般導覽參數不改變目標身份。
5. 無效 metadata 或無法解析的啟動設定保留上一個可用目標；此行為不代表無效設定成功連線。

核心 API 的 HTTP／WebSocket 傳輸與 LocalAPI 能力使用同一個解析結果。不能僅憑已儲存 ID 決定把請求送到 daemon。

### 首次接入

選中並連上本機 daemon、目前缺少可用配置時，首屏提供「登入 XBond」「匯入配置」「連接遠端控制器」。登入與三種匯入方式保留既有流程；本規格新增的遠端路徑不需要先完成登入或匯入。

連接遠端開啟空白的新增表單，支援名稱、地址、憑據與連接測試。成功儲存會產生新的控制器 ID 並選中它，不改寫內建 daemon 項。取消保留原有狀態。連接測試與儲存分開：儲存不是連通成功的證據。

已有遠端目標，包括啟動參數指定的遠端，不受本機是否有配置或 Cloud 登入狀態影響。登入等待或本機無服務時仍可選擇連接遠端；既有登入作業仍由 daemon 管理，切換目標不表示已取消它。

## 邊界與失敗

- 遠端視圖不暴露本機 LocalAPI client、配置、狀態或啟停／接管操作；誤用本機操作明確失敗，不靜默返回成功。
- 已配置本機目標的身份不隨暫時失聯變成遠端；初次讀取失敗時保留本機錯誤與重試入口，未確認連通時不授予可寫的 LocalAPI client。
- 本機帳號與訂閱資料仍由 daemon 擁有；本規格沒有將其轉發到外部控制器，也沒有實作遠端 xbond 管理 API 的完整配對。
- 控制器連接錯誤仍沿用現有錯誤與測試指引；不放寬 Origin、跳過憑證或自動修改系統代理。
- 本次能力判定不等於原生 VPN、TUN、外部連通或 Cloud 登出的驗證。純 Web 也不會因選中遠端就接管目前設備流量。

## 驗收條件

| 編號 | 可判定結果 | 驗證入口 |
| --- | --- | --- |
| TARGET-01 | 已知 daemon 的內建目標取得本機能力；其他已儲存目標不取得 | `packages/client/tests/control-target.test.ts` |
| TARGET-02 | 帶控制器啟動參數的目標沿用預設 ID 仍使用遠端傳輸，不顯示本機配置與控制 | 目標解析測試；隔離瀏覽器指定遠端並讀取不同端口的設定 |
| TARGET-03 | metadata 必須匹配已知端點及憑據；已驗證頁面在 daemon 核心端點輪換後保持綁定；bridge 優先；一般導覽參數不改變本機身份；跨端點啟動不繼承上一目標憑據 | 目標解析測試；隔離瀏覽器狀態快照輪換 |
| TARGET-04 | 本機無配置時可新增、測試、儲存並選中遠端；內建項不被覆寫 | 隔離瀏覽器，使用可區分的本機／遠端接口替身，核對 storage 與請求 |
| TARGET-05 | 已儲存遠端與 URL 遠端不被本機首次接入流程阻擋，切換與路由模式操作不寫本機 LocalAPI | 隔離瀏覽器，核對遠端設定值與兩端寫入請求 |
| TARGET-06 | 三入口文案覆蓋全部語系；窄屏、深色、長文案、鍵盤操作與表單取消可用；本機讀取 503 顯示本機失敗與重試 | 型別檢查；桌面／窄屏瀏覽器檢查 |

## 已知限制

瀏覽器接口替身只驗證介面解析、傳輸去向與狀態，不證明真實核心、跨來源部署或代理出站成功。原生執行端與完整平台能力的接續，由 Cloud 的客戶端開發計劃與對應控制目標任務維護。
