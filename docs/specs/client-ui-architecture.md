# 用戶端資訊架構與頁面行為規格

本規格定義 XBond 用戶端在桌面版、流動版及純網頁控制器模式下的頁面職責、零重疊資訊架構、各模式可獲取資料與可執行操作，以及版面佈局契約。詞彙定義見 [GLOSSARY.md](../../GLOSSARY.md)，產品定位見 [PRODUCT.md](../../PRODUCT.md)，視覺系統與設計令牌見 [DESIGN.md](../../DESIGN.md)。

已確認的設計為桌面八入口、流動 App 四主入口，以及緊湊／標準／寬屏三檔響應式；共用視覺及元件規則見 [DESIGN.md](../../DESIGN.md)，逐頁內容、互動與版面見[跨端體驗設計](../design/client-experience-proposal.md)。本文記錄目標行為與驗收，不表示設計已全部實作。首次接入與有效目標解析以[控制目標規格](./control-targets.md)為準，優先於下文僅按 LocalAPI 或控制器 ID 判定的舊識別描述。

## 範圍與入口

本規格適用於共享前端（`packages/client-ui/src/`）及其承載的桌面殼層（`apps/desktop/src-tauri/`）、本機守護進程接口（`internal/daemon/` 的 `/localapi/v0/*`）、核心控制接口（Clash 相容 REST／WebSocket API）與流動端橋接層（`mobile/`）。

### 現有問題診斷與重構原則

此前介面存在四項結構性缺陷，本規格以「單一頁面單一核心職責、跨頁面零重疊控件、狀態與操作就近閉環」予以根治：

1. **功能跨頁重疊**：此前首頁、代理頁、設定頁同時堆疊訂閱匯入表單、全部策略組清單、端口輸入框及接管模式開關，導致用戶分不清主入口。重構後，每項完整管理表單只屬於唯一專責頁面，首頁只保留高頻快捷卡與跳轉入口。
2. **首頁重點失焦**：此前桌面首頁將二十多個分流策略組平鋪成超長清單，擠佔首屏並造成右側留空。首頁以日常連線中心組織狀態、焦點節點、常用模式及配置／用量摘要，全量策略組歸還節點頁；不要求固定六卡或一屏塞滿所有資訊。
3. **模式與平台邊界混淆**：本機守護進程模式（具備 `LocalAPI`）與純外部控制器模式（僅具備 Clash API）、桌面寬屏與手機窄屏之間未清晰區分可獲取資料與可操作範圍。重構後，按運行模式與宿主能力動態裁切視圖，不展示無效空殼。
4. **摺疊隱藏與交互割裂**：取消首頁「狀態詳情」等摺疊塊，核心可達、流量接管與出口驗證三層狀態在首頁直接展開；測試診斷與網路設定從「設定」深層子頁拆出，配合桌面獨立導覽與手機聚合導覽。

## 模式矩陣：不同模式下有哪些資訊、可獲取甚麼、可操作甚麼

用戶端同時受三個正交的模式維度影響：**控制目標模式**、**流量接管模式**及**路由模式**。

### 1. 控制目標模式（Control Target Mode）

| 維度 | 本機服務模式（`LocalAPI` + 核心控制器） | 外部控制器模式（僅遠端或獨立 Clash／sing-box 控制器） |
| --- | --- | --- |
| **識別條件** | 探測到有效 `localapi-token`（Tauri IPC、HTML meta、URL 參數或本機儲存）且目標為本機守護進程 | 未配置 `LocalAPI` 或用戶在控制器選擇器切換至遠端控制器位址 |
| **可獲取資訊** | 引擎運行狀態（`running`、`pid`、`uptime`、`mixedPort`、`clashPort`）、三層狀態（`core`、`takeover`、`egress` 連通與延遲、焦點策略鏈）、活躍訂閱與全部訂閱清單（配額 `upload`/`download`/`total`、到期時間 `expire`、更新時間 `lastUpdated`、自動更新間隔）、本機偏好（`takeoverMode`、`routingMode`、`allowLan`）、核心版本、策略組與節點延遲、即時上下行速率、記憶體佔用、活躍連線快照、核心日誌流、規則清單、Doctor 診斷報告（本機與代理 DNS、直連與代理出口延遲、訂閱網關健康）、脫敏 BugReport | 控制器位址與名稱、核心版本與能力集（`sing-box`／`mihomo`／`clash`）、核心配置（端口、局域網開關、路由模式 `mode`、日誌等級）、策略組與節點延遲、代理提供者（`providers/proxies`）與規則提供者（`providers/rules`）、即時上下行速率、記憶體佔用（視核心支援）、活躍連線快照、核心日誌流、規則清單、DNS 查詢結果 |
| **可執行操作** | 啟動／停止／重啟代理核心（`up`/`down`/`restart`）、切換流量接管模式（`sysproxy`/`tun`/`port`）、切換路由模式（`rule`/`global`/`direct`）、修改混合端口與局域網共享、綁定 XBond 訂閱或匯入通用訂閱 URL、切換活躍訂閱、立即更新單個或全部訂閱、重命名與移除訂閱、選擇策略組節點（自動持久化至當前訂閱）、節點與策略組延遲測速、斷開單條或全部活躍連線、DNS 查詢與清理 FakeIP／DNS 快取、執行一键全面診斷（Doctor）與匯出脫敏診斷包（BugReport）、切換控制器 | 切換路由模式（`rule`/`global`/`direct`）、選擇策略組節點、節點與策略組延遲測速、更新代理提供者與規則提供者（若核心支援）、斷開單條或全部活躍連線、DNS 查詢與清理快取（視核心支援）、修改端口與局域網共享（僅 Clash／Mihomo 支援，sing-box 外部控制器為唯讀）、新增／切換／編輯控制器連線資訊 |
| **介面差異** | 完整顯示連線主開關、三層狀態卡、接管模式切換卡、訂閱配額環與訂閱管理頁、Doctor 全面診斷 | 頂部狀態卡標示「外部控制器模式（僅管理遠端核心，不含本機系統代理與 TUN 接管）」；隱藏本機引擎啟停按鈕與本機接管模式開關；「訂閱」頁改為展示控制器的 Proxy Providers（若支援）或提示由遠端實例管理來源配置 |

### 2. 流量接管模式（Takeover Mode，僅本機服務模式適用）

| 接管模式 | 狀態資訊與含義 | 可操作項與交互表現 |
| --- | --- | --- |
| **系統代理（`sysproxy`）** | 顯示系統 HTTP／SOCKS 代理是否已指向 `127.0.0.1:<mixedPort>`；三層狀態中「流量接管」為就緒（綠點），適合瀏覽器與支援系統代理的日常應用 | 點擊即切換並自動設定作業系統代理；停止核心或退出時自動還原系統代理設定 |
| **虛擬網卡（`tun`）** | 顯示 `sing-tun` 虛擬網卡是否已注入並接管全系統 TCP／UDP 流量；適合不遵循系統代理的命令行、遊戲與桌面應用 | 點擊切換為 TUN 模式並重載核心；若權限不足或核心啟動失敗，保留原狀態並明確提示所需系統權限 |
| **僅端口模式（`port`）** | 顯示核心僅監聽 `127.0.0.1:<mixedPort>`，不修改系統代理亦不建立虛擬網卡；三層狀態中「流量接管」明確標註「僅監聽本機端口，未接管全系統流量」（中性提示而非錯誤） | 點擊切換為僅端口模式並關閉系統代理；提供一鍵複製端口位址與環境變數命令（PowerShell／Bash） |

### 3. 路由模式（Routing Mode）

| 路由模式 | 流量走向與顯示資訊 | 對各頁面的影響 |
| --- | --- | --- |
| **規則分流（`rule`）** | 按生效規則智能匹配流量走向（如國內直連、海外走代理策略組） | 首頁「當前節點」卡片聚焦主策略組（如 `節點選擇`／`Proxy`）及其生效鏈路；「代理」頁展示全部業務與區域策略組 |
| **全局代理（`global`）** | 所有進入核心的流量統一走 `GLOBAL` 策略組指定的出口節點 | 首頁「當前節點」卡片自動切換為控制 `GLOBAL` 組；「代理」頁將 `GLOBAL` 置頂高亮 |
| **全部直連（`direct`）** | 所有流量直接連網，不經過任何代理節點 | 首頁「當前節點」卡片顯示「當前為直連模式，流量不經代理節點」，停用節點選擇下拉框以避免誤導 |

## 客戶端平台矩陣：不同客戶端呈現甚麼、可操作甚麼

| 客戶端平台 | 導覽架構與視窗佈局 | 專屬呈現資訊 | 專屬可操作項 |
| --- | --- | --- | --- |
| **桌面端（Tauri Desktop）** | 標準及寬屏為八入口浮島側欄＋任務工作區；緊湊時仍保留八入口抽屜。依三檔重排，不以寬度改變宿主身份 | 目前目標、配置、核心／接管／出口狀態及實際可取得的版本與量度資料 | 依宿主能力提供核心啟停、系統代理／TUN、配置管理、終端命令、托盤及診斷入口；未支援能力不放假控制項 |
| **流動端（Mobile App）** | 目標列＋四項底部導覽（首頁、節點、活動、設定）；內容按三檔適配，保留系統安全區 | 宿主 VPN 隧道狀態、目前節點與配置、來源可得的用量及量度資料 | 系統 VPN 授權及啟停、節點選擇、宿主支援的配置管理；規則及診斷保留次級入口，不照搬桌面接管選項 |
| **純網頁端（Browser Web UI）** | 緊湊用八入口抽屜、標準用完整側欄、寬屏可並列列表與已選詳情 | 目前控制器名稱／位址、連線狀態、核心版本及能力邊界 | 依 LocalAPI 或外部控制器的已確認能力管理目標，不因網頁連上控制器就宣稱本機已接管 |

## 頁面規劃與零重疊職責（規劃甚麼頁面、放甚麼、怎麼放）

為徹底消除功能重疊，桌面端規劃 **8 個專責頁面**，流動端收斂為 **4 個底部主分頁**（其餘 4 項能力以明確的二級視圖歸入對應分頁，不在首頁或設定重複堆砌相同表單）。

| 桌面端一級導覽（8 項） | 流動端歸屬位置（4 項底欄） | 頁面唯一核心職責 | 嚴禁跨頁重複的內容 |
| --- | --- | --- | --- |
| **1. 首頁**（`/connect`） | **首頁**（Tab 1） | 連線啟停、三層狀態總覽、主策略組快捷換節點、接管與路由模式快速切換、活躍訂閱配額概覽、即時流量趨勢 | 禁止放全量策略組列表、禁止放新增訂閱表單、禁止放端口修改輸入框、禁止放摺疊「狀態詳情」 |
| **2. 節點**（`/proxies`） | **節點**（Tab 2） | 全量策略組瀏覽、節點搜尋／排序／批量測速、節點切換、代理提供者（Proxy Providers）更新 | 禁止放接管模式開關、禁止放訂閱新增表單 |
| **3. 訂閱**（`/subscriptions`） | 首頁訂閱卡點擊進入，或 **設定 > 訂閱管理** | 新增訂閱（XBond 憑證／通用連結）、訂閱卡片列表、配額與到期詳情、切換使用、立即更新、重命名、複製連結、刪除 | 禁止放網路端口設定、禁止放規則列表或診斷工具 |
| **4. 連線**（`/connections`） | **活動 > 活躍連線**（Tab 3 分段 1） | 即時活躍連線明細監控、按關鍵字／規則／鏈路過濾、查看單條連線詳情、一鍵斷開單條或全部連線 | 禁止與設定頁混放 |
| **5. 規則**（`/rules`） | **設定 > 分流規則**（或代理頁、連線詳情的快捷連結） | 分頁檢索分流規則、查閱連線回報的命中規則、獨立管理規則集與全域覆寫 | 禁止在規則頁混放 DNS 查詢表單或 Doctor 診斷 |
| **6. 日誌**（`/logs`） | **活動 > 核心日誌**（Tab 3 分段 2） | 即時核心日誌流查看、按等級（`info`/`warning`/`error`/`debug`）與關鍵字過濾、暫停／繼續滾動、清空顯示 | 禁止在首頁直接塞入日誌列表 |
| **7. 診斷**（`/diagnostics`） | **設定 > 網絡測試與診斷** | 常用網站連通與延遲測試、DNS 解析查詢、清理 DNS／FakeIP 快取、本機 Doctor 全面健檢（含出口與網關檢查）及匯出脫敏報告 | 禁止將診斷 JSON 原文直接裸露堆砌在設定首屏 |
| **8. 設定**（`/settings`） | **設定**（Tab 4） | 系統與核心設定（本機混合端口、局域網共享、一鍵複製終端代理命令）、外觀與語言設定、外部控制器管理、版本與環境資訊 | 禁止在設定頁重複放置訂閱新增表單、規則列表或 DNS 測試表單 |

## 各頁面詳細設計（放甚麼、怎麼放、可獲取與可操作細節）

### 1. 首頁（`/connect`）—— 日常連線中心

- **主操作**：按目標與宿主提供啟動／停止代理、手機 VPN 連接／中斷，或遠端管理／重新連接；核心、接管及出口分開呈現，必要狀態不摺疊。
- **當前節點**：顯示焦點策略組、目前節點及最近一次延遲口徑。點選開啟節點選擇面板，不平鋪全量策略組；成功後才更新選中，失敗保留原值。
- **常用模式**：接管方式與路由模式有各自標籤及效果說明，依目標與宿主能力呈現；手機 VPN 不機械複製桌面三種接管方式。
- **配置與用量**：配置摘要可進訂閱，速率、核心累計與訂閱配額分開。只有真實樣本才繪製走勢，來源中斷標明資料狀態。
- **版面**：緊湊依「連線、節點、模式、配置及用量」單欄排列；標準採原生感連線主卡與節點／偏好輔助區；寬屏保持雙區重心，下方摘要可並列。首頁無重複大頁名、完整匯入表單、端口／局域網表單或日誌列表，也不要求所有內容塞進手機首屏。

### 2. 節點頁（`/proxies`）—— 策略組與節點工作台

- 依次呈現目前策略組、搜尋／排序／測速及候選列表。每列先放名稱、必要來源、延遲與選中標記，技術鏈路進詳情；延遲未知、測試中與失敗分開。
- 緊湊及標準使用策略組選擇器與連續列表，寬屏可與已選詳情並列，不常駐第三條策略目錄；測速參數進對應工具，切換時斷開舊連線的偏好在設定管理。
- 自動策略組和直連模式依真實語義呈現，不能放沒有作用的手動切換。Proxy Providers 依控制器支援提供更新及健康檢查入口。
- 選節點保留組別、搜尋及捲動脈絡；面板形態改變不重送選擇。詳情與測速不掩蓋核心未啟動或目標失聯的狀態。

### 3. 訂閱頁（`/subscriptions`）—— 來源配置與配額中心

- 使用中配置優先，其他配置依相同語義列表呈現；先看名稱、來源、有效性、最近更新，再看來源可得的配額、有效期及自動更新資訊。
- 「新增配置」為單一入口，進入後依宿主能力選登入 Cloud、連結、檔案或貼上；匯入完成表示配置已加入，不直接表示正在代理。失敗保留輸入，更新失敗保留上一份可用配置。
- 使用／更新是就近主要操作，重新命名、複製、覆寫、編輯及移除進詳情或更多選單；沿用既有確認及執行語義，清楚說明作用對象和影響。
- 緊湊詳情及編輯為全屏任務，標準按需抽屜，寬屏可列表與詳情並列。配額用文字及適量圖形表達，不同時堆疊多個等義圖形，也不把每個管理動作永久鋪滿卡尾。

### 4. 連線頁（`/connections`）—— 即時活躍連線明細

- 頂部為精簡速率／連線摘要、搜尋、篩選及必要排序；斷開全部與日常查閱操作分開，保留影響確認。
- 主要記錄優先呈現應用／目標、策略、速率及持續時間；IP、端口、規則、完整鏈路與來源可得的進程資料進詳情。
- 緊湊為摘要列進詳情，標準為資料表及按需抽屜，寬屏可讓列表與已選詳情同屏；尚無選擇不展示空詳情框。
- 暫停刷新、即時來源中斷及沒有活躍連線是不同狀態。更新資料及窗口縮放不移走焦點或清除選中、搜尋與捲動位置。

### 5. 規則頁（`/rules`）—— 分流規則與規則集檢索

- **分流規則**：本機 daemon 從運行中的核心讀取規則，每頁最多顯示 50 條。以匹配內容、規則類型或出口搜尋，結果顯示命中數並保留核心的原始序號。外部 Clash 相容控制器提供全量列表，使用者可主動載入後分頁查閱。
- **連線命中**：連線詳情可帶入核心回報的規則資訊，查找目前配置中的對應條目。同一回報可能對應多條候選規則，也可能因配置已更新而找不到條目。
- **來源與覆寫**：規則集與全域覆寫各有獨立分頁。支援規則集的核心可查看名稱、類型、條數、上次更新時間並更新個別規則集。全域覆寫由本機 daemon 管理。

### 6. 日誌頁（`/logs`）—— 核心運行日誌流

- **頂部控制列**：日誌等級過濾分段器（`全部`、`Info`、`Warning`、`Error`、`Debug`）、關鍵字搜尋框、「暫停滾動／繼續跟隨」按鈕、「清空畫面」按鈕。
- **主體等寬日誌流**：每行顯示時間戳、語義色等級標籤（`INFO` 藍、`WARN` 橙、`ERROR` 紅）及完整訊息內容，支援選取與複製單行日誌。

### 7. 診斷頁（`/diagnostics`）—— 連通檢測、DNS 與全面診斷

將所有排障與測試工具集中於此頁，分為三個清晰功能區塊：

- **區塊一：常用服務連通與延遲測試（Connectivity Benchmark Cards）**
  - 頂部設「全部測試」按鈕；下方以网格卡片展示關鍵目標（如 `Google / gstatic 204`、`GitHub`、`Apple`、`Cloudflare` 或自訂測速 URL），透過核心代理測試各目標連通性與回應毫秒數，直觀驗證當前節點是否可用。
- **區塊二：DNS 解析查詢與快取清理（DNS Inspector & Cache Control）**
  - 輸入域名（如 `example.com`）與記錄類型（`A`、`AAAA`、`CNAME`、`HTTPS` 等）發起核心 DNS 查詢，結構化表格展示耗時（ms）、回應狀態碼（`NOERROR` 等）及 Answer／Authority 記錄；旁設「清理 DNS 快取」與「清理 FakeIP 快取」按鈕（按核心能力顯示）。
- **區塊三：本機全面健檢與診斷包（XBond Doctor & BugReport，本機服務模式專屬）**
  - 點擊「執行全面健檢（Doctor）」，將 `DoctorReport` 結構化渲染為 4 張可視化檢查卡（**絕不直接裸露原始 JSON**）：
    1. `三層狀態核驗`：核心可達、流量接管、代理出口延遲與焦點策略鏈。
    2. `DNS 對比檢測`：本機系統 DNS 解析結果（`localDnsSuccess` + IP）對比代理 DNS 解析結果（`proxyDnsSuccess` + IP）。
    3. `直連與代理出口對比`：本機直連耗時（`directLatencyMs`）對比代理出口耗時（`proxyLatencyMs`）。
    4. `訂閱網關健康`：主網關（`primaryOrigin`）與備用網關（`fallbackOrigins`）連通狀態。
  - 旁設「匯出脫敏診斷包（BugReport）」按鈕，一鍵下載已自動脫敏憑證與敏感欄位的 JSON 檔案供技術支援排查。

### 8. 設定頁（`/settings`）—— 裝置、網絡與介面偏好

以「常規、網絡、進階、關於」四分類組織，採分組卡片與連續設定行，依三檔自然重排：

- **常規**：語言、主題、動態效果、節點切換偏好，及宿主已確認可讀寫的啟動／關窗偏好。
- **網絡**：混合端口、跟隨配置／覆寫來源、局域網共享、終端代理命令與格式選擇；接管說明及可用選項依宿主能力呈現。
- **進階**：控制器新增及編輯、核心相關能力、規則與診斷次級入口。常駐控制目標選擇器與帳號入口不藏入此分類。
- **關於**：介面與核心版本、實際取得的環境資料、說明與報告入口；沒有資料來源時不虛構 `platform`／`arch`。

緊湊單欄、標準分組、寬屏可並列獨立設定組；同一設定行的標籤與控制項保持鄰近，錯誤及儲存回應跟隨相關欄位。搜尋設定須有真實索引才提供；訂閱新增、完整規則及 DNS 工具不在設定重複表單。

## 邊界與失敗處理

- **無訂閱或首次啟動**：首頁連線主卡明確顯示「尚未加入訂閱配置」，主按鈕變為「新增訂閱」（點擊跳轉至 `/subscriptions`），不展示空白錯誤或假成功。
- **核心未啟動時的操作保護**：在核心未啟動時進入「代理」、「連線」、「規則」或「日誌」頁，展示平實的空狀態提示卡（「代理核心尚未啟動，請先返回首頁啟動連線以載入即時資料」）並附「返回首頁」按鈕，不拋出未捕獲的網路異常。
- **外部控制器模式降級**：當 `hasLocalAPI` 為 `false` 時，所有依賴本機守護進程的操作（啟停引擎、系統代理／TUN 切換、本機訂閱增刪、Doctor 健檢）平穩隱藏或標註「由遠端控制器管理」，絕不發起會失敗的 `/localapi/v0/*` 請求。
- **切換節點或修改設定失敗**：保留原有選中狀態與用戶輸入值，就近顯示錯誤原因與重試途徑，不以樂觀更新掩蓋失敗。

## 驗收條件

- **AC-1（導覽與路由零重疊）**：桌面及完整 Web 保留首頁、節點、訂閱、連線、規則、日誌、診斷、設定八入口，緊湊抽屜與標準／寬屏側欄可到達相同目的地；流動 App 四項底欄為首頁、節點、活動、設定，次級訂閱、規則及診斷可達。縮放不改變控制目標或路由。
- **AC-2（連線中心與狀態）**：首頁優先呈現主操作及真實狀態、當前節點、常用模式、配置與用量摘要；必要三層事實直接可見，不平鋪全量策略組、匯入及網絡表單。緊湊、標準、寬屏按 DESIGN.md 重排，詳情與待處理操作在切換版面後保持連續。
- **AC-3（頁面專責化）**：訂閱頁承接完整配置管理，規則頁承接分流規則與來源，診斷頁承接連通／DNS／Doctor 及報告，設定承接常規、網絡、進階及關於；首頁提供高頻捷徑及摘要，不複製完整管理表單。
- **AC-4（模式與客戶端自適應）**：依目前控制目標及宿主能力呈現模式與操作；桌面核對系統代理／TUN／僅端口及規則／全局／直連，手機本機核對系統 VPN 授權與隧道狀態，外部控制器不取得本機接管能力。核心未啟動時各依賴頁顯示明確引導，不能因版面相同合併不同宿主的事實。
- **AC-5（視覺、響應式與無障礙）**：依 [DESIGN.md](../../DESIGN.md) 驗證玻璃浮島、大圓角、明暗對比、鍵盤、減少動態及香港繁體用語；以手機、960 × 720 客戶端、寬屏 Web 為三檔重點，補短視窗、鍵盤、長文案、縮放及 2K／4K，操作不被遮擋且沒有全頁橫向溢出。實施後執行相關型別、lint、測試、建置與有界視覺驗證，本次文件更新不視作通過。
